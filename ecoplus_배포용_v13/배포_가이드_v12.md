# ecoplus100.com v12 배포 가이드

v11 → v12 변경분을 반영하고, GitHub 유지보수 체계와 방문·클릭 분석을 켜는 절차입니다.
**순서대로 진행하세요. 3번(Apps Script)을 먼저 끝내야 사이트에 URL을 넣을 수 있습니다.**

---

## 1. v12에서 바뀐 것

| 구분 | 내용 |
|---|---|
| 무료진단 | 홈페이지 안의 상담신청 모달을 제거하고, **ecofree.cloud 1분 자가진단**으로 연결 (8곳) |
| 기존 링크 보호 | 전단지·QR에 쓰인 `ecoplus100.com/?diag=1` 은 자동으로 진단 페이지로 이동 |
| 짧은 주소 | `ecoplus100.com/진단`, `/diagnosis` 도 진단 페이지로 연결 (netlify.toml) |
| 분석 | 전 페이지에 `eco-track.js` + GA4 삽입. 방문·클릭·스크롤·진단·결제 퍼널 수집 |
| 도메인 연결 추적 | ecoplus100.com → ecofree.cloud 이동 시 방문자 ID를 `_ev` 파라미터로 인계 |
| 유지보수 | `.gitignore` 추가, GitHub 연동 배포로 전환 |

### 사라진 기능 (의도된 것)
홈페이지 안의 상담신청 폼(Netlify Forms `diagnosis`)이 없어집니다.
앞으로 상담 신청은 **전부 ecofree.cloud → Supabase**로 모입니다. 지금까지 홈페이지 폼으로 들어온
기존 접수 내역은 Netlify 대시보드의 Forms 탭에 그대로 남아 있으니 필요하면 먼저 내려받아 두세요.

## 2. 먼저 손봐야 할 것 두 가지

### (1) 토스 결제 키가 테스트 키입니다
`index.html` 안에 `TOSS_CLIENT_KEY = 'test_ck_...'` 로 되어 있습니다.
**현재 운영 사이트도 동일한 테스트 키라 실제 결제 승인이 되지 않습니다.**
토스페이먼츠에서 라이브 키를 발급받아 교체하고, Netlify 환경변수의 시크릿 키도 함께 맞춰야 합니다.
이번 작업 범위 밖이라 그대로 두었습니다.

### (2) 관리자 비밀번호가 코드에 그대로 있습니다
`admin-login.html` · `admin.html` 안에 `DEFAULT_PASSWORD = 'ecoplus2026!'` 이 평문으로 들어 있습니다.
→ **GitHub 저장소는 반드시 Private 으로 만드세요.** Public 으로 올리면 누구나 볼 수 있습니다.

## 3. Google Apps Script 분석 설치

### 3-1. 스프레드시트와 스크립트 만들기
1. Google Sheets 새 문서 생성 → 이름을 **"에코플러스 방문분석"** 으로 저장
2. 상단 메뉴 **확장 프로그램 → Apps Script**
3. 편집기의 기본 코드를 모두 지우고, `google-apps-script/Code.gs` 내용을 **전체 복사·붙여넣기** → 저장
4. 함수 선택 상자에서 **`초기설정`** 을 고르고 **실행**
   - 처음 실행하면 권한 승인 창이 뜹니다. `고급 → 안전하지 않음(이동)` 을 눌러 승인하세요.
   - 완료되면 시트에 `이벤트` / `일별요약` / `유입경로` / `CTA클릭` 4개 탭이 생깁니다.

### 3-2. 웹 앱으로 배포
1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴 → **웹 앱** 선택
3. 설정
   - 설명: `tracker v1`
   - **실행 계정: 나**
   - **액세스 권한: 모든 사용자** ← 이걸 빠뜨리면 데이터가 하나도 안 들어옵니다
4. 배포 → 나오는 **웹 앱 URL** 복사
   (`https://script.google.com/macros/s/AKfy............/exec` 형태)
5. 그 URL을 브라우저에 붙여넣어 보세요.
   `{"ok":true,"service":"ecoplus-tracker","version":"1.0"}` 가 보이면 정상입니다.

### 3-3. 사이트에 URL 넣기
아래 파일들에서 `GAS_WEBAPP_URL_HERE` 를 **복사한 /exec URL** 로 바꿉니다. (전체 8곳)

```
ecoplus_배포용_v12/index.html
ecoplus_배포용_v12/ecoplus_policy_fund.html
ecoplus_배포용_v12/ecoplus_startup_fund.html
ecoplus_배포용_v12/ecoplus_rnd_center.html
ecoplus_배포용_v12/ecoplus_venture_cert.html
ecoplus_배포용_v12/success.html
ecoplus_배포용_v12/fail.html
ecoplus_배포용_v12/refund-policy.html
```

진단 사이트는 별도입니다.
```
eco-diagnosis_v2.5_교체파일/index.html   ← 여기도 GAS_WEBAPP_URL_HERE 1곳
```

> 메모장으로 하나씩 고쳐도 되지만, VS Code 같은 편집기에서 폴더 전체 열고
> `Ctrl+Shift+H`(전체 바꾸기)로 한 번에 처리하는 게 안전합니다.

### 3-4. 코드를 고칠 때마다 재배포
Apps Script 코드를 수정했다면 **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**
를 눌러야 반영됩니다. URL은 그대로 유지됩니다.

## 4. GA4 설치

1. https://analytics.google.com → 관리 → 속성 만들기 → 웹 데이터 스트림 추가
   - 스트림 1: `https://ecoplus100.com`
   - 스트림 2: `https://ecofree.cloud`
   - **두 사이트를 하나의 속성 안에 두 스트림으로** 만들면 합산 통계를 볼 수 있습니다.
2. 발급된 **측정 ID** (`G-` 로 시작) 복사
3. 위 3-3과 같은 파일들에서 `G-XXXXXXXXXX` 를 실제 측정 ID로 전체 바꾸기 (파일당 3곳)
4. 배포 후 GA4 → 보고서 → 실시간 에서 본인 접속이 잡히는지 확인

> GA4를 쓰지 않으려면 각 파일 `<head>` 안의 `Google Analytics 4` 주석 블록을 지우면 됩니다.
> 지워도 Apps Script 수집은 그대로 작동합니다.

## 5. GitHub 저장소 만들기

### 5-1. 저장소 생성
1. https://github.com/new (계정 `ecoplus24`)
2. Repository name: **`ecoplus100`**
3. **Private 선택** (2번 항목 참고 — 관리자 비밀번호가 코드에 있음)
4. Create repository

### 5-2. 파일 올리기 (웹에서 드래그로 가능)
1. 만들어진 저장소 화면에서 **uploading an existing file** 클릭
2. `ecoplus_배포용_v12` 폴더 **안의 내용물 전체**를 드래그
   (폴더째가 아니라 안의 파일들을 올려야 `index.html` 이 최상단에 옵니다)
3. Commit changes

명령줄이 익숙하면:
```bash
git init && git add -A && git commit -m "v12: 무료진단 ecofree 연결 + 방문분석 도입" && git branch -M main && git remote add origin https://github.com/ecoplus24/ecoplus100.git && git push -u origin main
```

### 5-3. Netlify를 GitHub에 연결
1. Netlify → **eco-toss01** 사이트 → Site configuration → **Build & deploy**
2. **Link repository** → GitHub → `ecoplus24/ecoplus100` 선택
3. 빌드 설정
   - Build command: **비워둠**
   - Publish directory: **`.`**
   - Functions directory: **`netlify/functions`**
4. Deploy

> 도메인(ecoplus100.com), 환경변수, 기존 Forms 데이터는 그대로 유지됩니다.
> 연결 후에는 **GitHub에 커밋하면 자동 배포**됩니다. 드래그앤드롭은 더 이상 쓰지 마세요
> (드래그앤드롭으로 덮으면 서버 함수가 사라질 수 있습니다).

### 5-4. 진단 사이트 반영
진단 사이트는 이미 GitHub(`ecoplus24/ecoplus-diagnosis`)로 운영 중입니다.
`eco-diagnosis_v2.5_교체파일/index.html` **한 파일만** 저장소의 `index.html` 로 교체 커밋하면 됩니다.
(admin.html, netlify/functions 는 건드리지 않았습니다)

## 6. 배포 후 확인 체크리스트

- [ ] ecoplus100.com 접속 → 상단 "무료 진단 신청" 클릭 → ecofree.cloud 로 이동하는가
- [ ] 이동한 주소 끝에 `?_ev=...` 가 붙었는가 (도메인 간 방문자 추적이 붙은 증거)
- [ ] `ecoplus100.com/?diag=1` 접속 → 진단 페이지로 자동 이동하는가
- [ ] `ecoplus100.com/진단` 접속 → 진단 페이지로 이동하는가
- [ ] 상품 상세 4개 페이지의 "1분 무료 진단 신청" 버튼이 모두 진단으로 가는가
- [ ] Google Sheets `이벤트` 탭에 `page_view` · `click` 행이 쌓이는가 (수 초 내)
- [ ] 진단을 끝까지 진행 → `diag_start` `diag_step` `diag_result` `diag_submit` 이 기록되는가
- [ ] 진단 접수 후 Supabase 저장·알림톡이 **전과 동일하게** 작동하는가
- [ ] GA4 실시간 보고서에 접속이 잡히는가
- [ ] 다음날 새벽 3시 이후 `일별요약` 탭이 채워지는가 (급하면 `일별요약갱신` 수동 실행)

## 7. 알아두실 한계

- **Apps Script는 무료 계정 기준 하루 스크립트 실행시간 제한(약 90분)이 있습니다.**
  이벤트 1건당 1초 미만이므로 **일 수천 건까지는 여유**가 있지만, 트래픽이 크게 늘면
  누락이 생길 수 있습니다. 그 시점에는 GA4 수치를 기준으로 쓰시면 됩니다.
- **봇·크롤러 트래픽이 걸러지지 않습니다.** GA4 수치와 차이가 나면 대체로 이 때문입니다.
- 방문자 수는 **브라우저 저장소 기준**입니다. 같은 사람이 휴대폰·PC로 오면 2명으로 잡히고,
  시크릿 모드나 저장소 삭제 시 새 방문자로 잡힙니다.
- 이 시트에는 **이름·연락처·IP가 저장되지 않습니다.** 상담 신청 내용은 기존대로 Supabase에만 있습니다.
